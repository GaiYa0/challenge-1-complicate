# 关系网络可视化改造方案（规划文档）

> 本文档仅描述目标、问题诊断与实施计划，**不包含具体代码**。  
> 参考界面：  
> - 现状问题（节点堆叠）见工作区截图；  
> - 目标交互与信息架构（左图 G6 + 右栏「人物画像与风险提示」）见 `1271775866656_.pic-*.png`（下称 **p2 参考**）。

---

## 一、背景与目标

项目聚焦**职务犯罪侦查线索挖掘**，关系网络页需要同时解决：

1. **可读性**：图谱不再挤成一团，结构一目了然。  
2. **业务语义**：选中一名涉案人员后，以其为中心，**按风险等级从高到低、由内向外**展示与其关联的**线索节点**（球体），颜色区分：**红 / 黄 / 深蓝** 分别对应高 / 中 / 低风险。  
3. **可钻取**：每个线索球可点击，**右侧（或弹层）展示与 p2 参考一致的详情**：姓名/实体名、风险标签、规则命中、特征摘要、风险提示等。

## 二、现状问题诊断（为何会出现「全部堆叠」）

结合当前实现（`frontend/src/components/graph/GraphView.vue`、`frontend/src/pages/RelationshipNetwork.vue`）与常见力导向表现，堆叠可能来自：

| 因素 | 说明 |
|------|------|
| **画布高度固定偏小** | Neo4j 模式下 G6 图高度写死为 **320px**，而页面外层 `graph-container` 有更大 `min-height`，力导向在**过矮的视口**内迭代，节点易挤在中心区域。 |
| **力导向参数与规模不匹配** | `linkDistance`、`nodeStrength`、`preventOverlap` 与 `nodeSize` 需与**实际节点数、边密度**联动；边多或节点多时，默认参数容易在有限区域内收敛成「一团」。 |
| **标签占位未计入碰撞** | 节点下方中文标签占用额外视觉空间，若碰撞体积仍以圆心半径估算，**视觉上仍会重叠**。 |
| **缺少初始分散或后处理** | 未在布局结束后做 `fitView`、未对过近节点做二次微调时，初次渲染可能呈现「糊在一起」。 |

> 结论：需**布局参数与容器尺寸联动调优**，必要时**更换或组合布局算法**（见下文），而非仅调一两个魔法数。

## 三、任务 1：让关系网络「显示恢复正常」

### 3.1 目标

- 节点在可视区域内**分散可辨**，标签尽量不重叠；支持拖拽、缩放后仍保持清晰。  
- 大图场景下可考虑**限制首屏边数/节点数**或**聚合**（与现有「裁剪」思路一致），避免一次渲染过载。

### 3.2 计划项（前端）

1. **尺寸与容器**  
   - 将 G6 画布高度与 **父级 `graph-container` 实际高度** 绑定（或统一为不小于 480px～600px 的合理区间），避免「外大内小」导致力导向在窄带内挤压。  
   - 监听窗口与容器 `ResizeObserver`，**重算 `graph.resize` 与 `layout` 重新执行**（或仅在尺寸变化超过阈值时重跑）。

2. **力导向调参**  
   - 按节点数分档：例如节点数 &lt; 30 / 30～100 / &gt;100 使用不同的 `linkDistance`、`nodeSpacing`、`collideStrength`、`alpha`（迭代次数或衰减）。  
   - 确认 `preventOverlap` 与 **节点样式中的 `size`**、**标签 `labelOffsetY`** 在语义上一致（必要时加大碰撞半径）。

3. **备选布局**  
   - 若纯力导向仍不理想：  
     - **有向图**可尝试 **dagre**（分层清晰）或 **combo + force**；  
     - **无向社交网**可尝试 **forceAtlas2**（G6 若支持）或 **circular / radial** 作为「默认视图」切换。  
   - 提供 UI 切换：**「力导向 / 层次 / 环形」**（可选，便于演示与对比）。

4. **布局后处理**  
   - `render` 后调用 **fitView / focus** 使全图进入视口；  
   - 对极端重叠可考虑 **节点略作随机扰动** 或 **增大画布** 再跑一次 `layout`。

5. **边与多边**  
   - 同一对节点多条边时，使用 **曲线偏移 / 多线 bundling** 或 **边聚合**，减少视觉混乱。

### 3.3 验收

- 使用与截图同规模或更大的 Neo4j 子图，**无严重中心堆叠**；主要节点可单独点击选中。  
- 缩放、拖拽画布后布局不崩溃。

## 四、任务 2：选中人物后，同心圆展示「线索球」（按风险由内向外）

### 4.1 交互流程

1. 用户在主图中 **点击某个「人」节点**（或从左侧列表选择），该节点成为 **焦点人物**（center）。  
2. 请求或读取该人物关联的 **线索列表**（每条线索带 `risk_level`：`high` | `medium` | `low`）。  
3. 以焦点为圆心，在 **同心圆** 上放置线索球：  
   - **最内圈**：高风险（**红**）；  
   - **中圈**：中风险（**黄**）；  
   - **外圈**：低风险（**深蓝**）。  
4. 同一风险等级内多条线索，按**角度均分**分布在对应圆周上；若数量过多，**单圈分页或缩略 + 展开** 或 **螺旋多层**（避免单圈过密）。

### 4.2 数据模型（建议）

- **人物节点**：与现有 Neo4j `User` 或业务 ID 对齐。  
- **线索节点**（Clue）：至少包含：`id`、`title`/`summary`、`risk_level`、`related_person_id`、可选 `score`、`category`（资金/通话/轨迹等）。  
- 后端可提供：  
  - `GET /api/.../persons/:id/clues` 返回列表；或  
  - 分析任务完成后写入 PostgreSQL/Redis，前端按案件 ID + 人物 ID 拉取。

> 当前仓库若尚无「线索」实体，需 **新增 schema + 接口** 或 **mock 数据** 先完成演示；规划阶段需产品确认线索来源（规则引擎结果 / 人工标注 / 离线脚本）。

### 4.3 可视化实现思路（G6）

- **模式 A**：主图仍用力导向；选中人物后 **切换** 为「径向 + 同心圆」子图（仅中心 + 线索球 + 可选连线到中心）。  
- **模式 B**：主图保持，**叠加一层** 自定义 Canvas/SVG 在右侧区域绘制同心圆（与 G6 解耦，但需统一坐标系与 DPI）。  

推荐 **模式 A**（同一 G6 实例内切换 `data` 与 `layout`），避免双引擎同步问题。

- **布局**：使用 **radial** 或自定义 `layout`：按 `risk_level` 映射到半径 `r_high &lt; r_medium &lt; r_low`；角度 `2π * i / n_k`。  
- **样式**：`node.style.fill` 按风险映射为 **红 / 黄 / 深蓝**；中心人物可用 **不同形状或描边** 与线索球区分。

### 4.4 验收

- 选中不同人物，同心圆 **仅** 展示该人物关联线索；颜色与风险等级一致。  
- 风险顺序 **由内到外** 固定为 高 → 中 → 低。

## 五、任务 3：点击线索球 → 展示 p2 式详情

### 5.1 信息架构（对齐 p2 参考）

- **标题区**：实体名称（或线索标题）+ **风险：高/中/低（百分比）** 醒目标签。  
- **摘要**：一句话概括（如资金异常、关联企业等）。  
- **标签**：多个可点击或静态标签（资金异常、关联企业、通话密集等）。  
- **规则命中**：列表展示触发的规则名称（如「单笔超阈值」「介数中心性 Top 10%」等）。  
- **特征摘要**：表格或键值对（如近 30 日转出、关联账户数、去重通话对象数等）。  
- **风险提示**：分级列表（红/黄条目），每条含简短说明。

### 5.2 前端结构建议

- **左右分栏布局**（与 p2 一致）：  
  - **左侧**：G6 图谱（主图 + 同心圆线索模式）。  
  - **右侧**：`Drawer` / 固定 `aside`（宽度 360px～420px），**选中线索球** 时填充内容；未选中时可显示占位说明或上次选中人物的基础信息。  
- **状态**：`selectedPersonId`、`selectedClueId`；点击线索球时 **仅更新右栏**，避免整页刷新。  
- **数据来源**：  
  - 若列表接口已含摘要，点击可 **不再请求**；  
  - 若详情字段多，使用 **GET `/clues/:id`** 拉全量。

### 5.3 验收

- 任意线索球点击后，右栏 **与列表项一致** 且 **无空白关键字段**（mock 阶段可标「示例数据」）。  
- 键盘可访问性、移动端可后续迭代（非必须）。

## 六、与现有页面的关系

| 文件/模块 | 调整方向（概要） |
|-----------|------------------|
| `GraphView.vue` | 支持双模式布局（主图 / 同心圆线索）；高度与容器绑定；节点点击向外暴露事件。 |
| `RelationshipNetwork.vue` | 改为左右分栏；引入右栏详情组件；接入人物选中、线索选中状态与 API。 |
| 新增 `ClueDetailPanel.vue`（名称可定） | 承载 p2 式详情区块。 |
| 后端 | 可选新增线索查询 API；或与 Neo4j/PG 中分析结果表对接。 |

## 七、实施顺序建议

1. **先解决布局与画布尺寸**（任务 1），确认主图可读。  
2. **再接入线索数据契约与 mock**（任务 2 数据部分）。  
3. **实现同心圆布局与三色球**（任务 2 视觉）。  
4. **最后做右栏详情与联调**（任务 3）。  

---

## 八、风险与依赖

- **数据**：若无真实线索数据，需先 mock，避免阻塞 UI。  
- **性能**：单人物关联线索数若超过 50～100，需分页或聚合展示。  
- **合规**：详情文案需保留「辅助分析、需人工复核」类提示（与项目合规表述一致）。

## 九、附录：颜色与语义约定（建议写进设计规范）

| 风险 | 颜色 | 球体语义 |
|------|------|----------|
| 高 | 红 | 优先核查 |
| 中 | 黄 | 关注 |
| 低 | 深蓝 | 备查 |

中心人物节点建议 **中性色（如灰/白底 + 描边）** 或 **固定品牌色**，避免与三色线索混淆。
