## 二、关系网络专项（part2 延伸）— 前端任务

以下任务对应「主图可读 → 选人 → 同心圆线索 → 右栏详情」的完整体验，文件落脚点以现有代码为准：`GraphView.vue`、`RelationshipNetwork.vue` 及新建组件。

### 2.1 布局与画布（解决堆叠）

1. **动态尺寸**  
   - 将 G6 实例的 `width`/`height` 与 `.graph-container`（或专用 ref）的 **实际 clientWidth/clientHeight** 绑定，最低高度建议 **≥ 480px**（与 part2 一致），避免 320px 矮画布导致力导向挤成一团。  
   - 使用 `ResizeObserver` 监听容器，在尺寸变化时调用 `graph.resize`，并视情况 **重新触发 layout**（需防抖，避免拖拽窗口时疯狂重算）。

2. **力导向参数分档**  
   - 根据 `nodes.length`（及可选 `edges.length`）划分档位（如 &lt;30、30～100、&gt;100），为每档配置不同的 `linkDistance`、`nodeSpacing`、`nodeStrength`、`collideStrength`、`alphaDecay` 等。  
   - 将 **节点圆半径 + 标签预估高度** 折算为碰撞有效半径（或增大 `nodeSize` 用于防重叠），减轻「圆不重叠但字重叠」。

3. **布局后处理**  
   - 在首次 `render` 完成后调用 **fitView / focusItem**（以当前 G6 API 为准），保证全图进入视口。  
   - 可选：监听 `afterlayout` 类事件后再 fit 一次，避免异步布局未完成就 fit。

4. **备选布局与 UI**  
   - 增加 **布局切换控件**（力导向 / 层次 Dagre / 环形等，以 @antv/g6 当前版本支持的 `layout.type` 为准），便于演示与兜底。  
   - 有向资金图可优先尝试 **分层布局**，减轻杂乱感。

5. **边渲染**  
   - 对 **重复边**（同 source/target 多条）采用曲线、不同 `offset` 或聚合展示，降低交叉与视觉糊团。

6. **性能**  
   - 与后端 `edge_limit` 或前端裁剪策略对齐：超量节点时 **分页、聚合、仅显示 k 跳子图**，并在 UI 上提示「已截断」。

### 2.2 交互模式：主图 → 同心圆线索视图

1. **状态机**  
   - 维护视图模式：`main` | `clueRadial`（命名可自定）。  
   - 维护 `selectedPersonId`（或 Neo4j 节点 id）、`selectedClueId`。

2. **主图点击**  
   - 监听节点 `click`：若类型为「人」，则切换为 `clueRadial`，并触发 **拉取该人物线索列表**（见后端章节）。  
   - 提供「返回全图」按钮，恢复 `main` 模式并重绘原 `neo4jData`。

3. **同心圆布局（G6 内实现，推荐 part2 模式 A）**  
   - 构造新 `data`：中心 1 个焦点节点 + N 个线索节点。  
   - 按 `risk_level` 分三层半径：内圈红（high）、中圈黄（medium）、外圈深蓝（low）；同层按角度均分 `2π*i/n`。  
   - 线索节点样式：填充色按风险；中心节点用 **不同形状/描边** 与线索球区分。  
   - 若单圈线索过多：分页、折叠为「+N」聚合节点，或 **螺旋增加半径**（需产品确认上限）。

4. **图例与文案**  
   - 页面固定区域展示 **红 / 黄 / 深蓝** 与高中低风险对应关系；合规提示：「分析结果仅供参考，需人工复核」。

### 2.3 线索详情侧栏（p2 信息架构）

1. **布局**  
   - `RelationshipNetwork.vue` 改为 **左右分栏**：左侧图谱 + 右侧固定宽度 aside（约 360～420px）或 `el-drawer`。  
   - 未选中线索时：显示占位说明或仅展示已选人物基础信息。

2. **组件**  
   - 新建「线索详情」组件（如 `ClueDetailPanel.vue`），区块包括：  
     - 标题 + 风险等级 + 分数/百分比  
     - 一句话摘要  
     - 标签组（Tag）  
     - 规则命中列表  
     - 特征摘要表格（键值对）  
     - 风险提示列表（按高/中分级样式）

3. **数据加载**  
   - 若列表接口已含详情所需字段，点击线索球 **仅切换本地状态**；否则调用 **GET 线索详情**（见后端）。  
   - 加载中/失败态：`loading`、`empty`、`error` 占位。

4. **可选增强**  
   - 顶部显示「已选节点：xxx」与 part2 参考一致；  
   - 键盘 Esc 关闭 drawer（若使用 drawer）。

### 2.4 API 封装与类型

1. 在 `frontend/src/api/` 下新增 **线索相关** 方法（路径与后端对齐）：如 `listCluesByPerson(caseId, personId)`、`getClueDetail(clueId)`。  
2. 定义 **TypeScript 类型**：`Clue`, `ClueRiskLevel`, `ClueDetail` 等，避免魔法字符串。

### 2.5 与其它页面的衔接

- **风险画像 / 调查报告**：若后续线索与报告同源，预留 **caseId + personId** 上下文，便于深链（本期可不做）。

## 三、关系网络专项（part2 延伸）— 后端任务

### 3.1 线索数据模型与持久化

1. **实体设计（PostgreSQL 推荐）**  
   - 表 `clues`（或 `investigation_clues`）：字段至少包括  
     - `id`（主键）  
     - `case_id`（外键关联案件）  
     - `person_id` 或 `person_key`（与 Neo4j `User` 的 name/id 映射规则需统一）  
     - `title`、`summary`  
     - `risk_level`（enum: high/medium/low）  
     - `risk_score`（0～100 可选）  
     - `category`（fund / call / trip / other）  
     - `rule_hits`（JSON 数组，存规则名称或编码）  
     - `feature_snapshot`（JSON，存特征摘要键值）  
     - `risk_prompts`（JSON，存分级提示文案）  
     - `created_at` / `updated_at`  
   - 若短期无持久化：可用 **JSON 文件 + 版本化 seed** 或 **内存 mock**，但接口形状应与正式表一致，便于替换。

2. **与 Neo4j 对齐**  
   - 明确 **人物主键**：Neo4j 节点 `User.name` 还是独立 `business_id`；前后端与 PG 必须使用 **同一套映射**（否则线索挂不上人）。

### 3.2 API 设计（FastAPI）

1. **列表**  
   - `GET /api/cases/{case_id}/persons/{person_key}/clues`  
   - 返回该人物在该案件下的线索数组（供同心圆渲染）。  
   - 鉴权：仅案件属主或 admin 可访问（与现有 `case` / `user` 权限模型一致）。

2. **详情**  
   - `GET /api/clues/{clue_id}`  
   - 返回完整详情（规则命中、特征摘要、风险提示等），供右栏使用。

3. **可选**  
   - 管理员或脚本：`POST/PATCH` 线索（人工录入、导入）；**演示阶段可省略**。

### 3.3 线索数据来源（与 part1 衔接）

- **长期**：由「规则引擎 / 分析任务」写入 `clues` 表（见 part1「碰撞与画像」）。  
- **短期**：  
  - **Seed 脚本** 或 **SQL 初始化** 插入若干条与 Neo4j 人名一致的示例数据；  
  - 或 Celery 任务根据 **mock 规则** 从现有 CSV 特征生成伪线索（需额外开发，归入算法侧）。

### 3.4 性能与安全

- 列表接口对单人物线索数做 **上限**（如 200），超出返回 `truncated: true`。  
- 响应中敏感字段按合规要求 **脱敏**（与 part1 合规项联动：手机号、账号中间位等）。

## 四、PDF / 产品级缺口（part1）— 前端任务

### 4.1 数据导入与字段映射

1. **上传组件增强**  
   - 多格式入口：在 UI 上区分 **CSV / Excel / TXT / PDF**（即使后端暂未全支持，也可先做 **引导与错误提示**）。  
   - **字段映射向导**：步骤条展示「上传 → 自动识别列 → 用户调整映射 → 确认导入」，映射结果以 JSON 提交后端。

2. **案件维度文件列表**  
   - 数据导入页、分析页 **仅展示当前 `caseId` 下文件**（与 `dataset=case-{id}` 或未来 `case_file` 表对齐），避免「全局 listDbFiles」造成误操作。

3. **导入报告展示**  
   - 展示清洗行数、去重数、丢弃原因等（依赖后端返回结构化报告）。

### 4.2 多维可视化

1. **时间轴组件**：基于 ECharts timeline 或自研 SVG，展示事件/流水时间分布（数据来自后端聚合接口）。  
2. **地图热力**：接入国内合规地图 SDK（或静态底图 + 热力层），展示轨迹/共现（依赖后端 GeoJSON 或点列）。  
3. **资金流向专图**：与通用关系图拆分路由或 Tab，强调 **金额边宽度、方向、路径**（数据来自后端图或序列数据）。

### 4.3 画像与报告

1. **四维画像 UI**：「经济状况、行为轨迹、社会关系、异常行为」四个 Tab 或折叠面板，每块绑定独立 API 字段。  
2. **线索摘要展示**：展示后端生成的摘要文本，支持复制。  
3. **导出**  
   - 调用后端 **PDF/Word 下载链接**，前端仅负责请求与 `blob` 下载；  
   - 保留 `window.print()` 作为兜底。

### 4.4 碰撞与规则（前端）

1. **规则配置界面**（若后端提供 DSL）：表单或低代码面板编辑规则条件、阈值、输出名称。  
2. **碰撞结果列表页**：表格列包括参与人、时间窗、可疑度、规则名、跳转详情。

### 4.5 安全与合规（前端）

1. 导出前 **二次确认**（「含敏感信息，需审批」类文案，与后端审批状态联动）。  
2. 敏感字段展示默认 **掩码**，支持「授权后查看全文」（依赖后端权限位）。

## 五、PDF / 产品级缺口（part1）— 后端任务

### 5.1 多格式解析与管道

1. **解除仅 CSV 限制**：在 `file_service` / `data_pipeline_service` 中按扩展名分支：  
   - Excel：`openpyxl`/`pandas.read_excel`  
   - TXT：编码探测 + 分隔符推断  
   - PDF：**pdfplumber** 或 **PyMuPDF** 表格提取；复杂版式引入 **OCR**（Tesseract/Paddle，独立服务或异步任务）  
   - 数据库：**仅支持受控场景**（预置连接串、只读账号、白名单表），通过异步任务导出为中间 CSV  
2. **统一中间表示**：解析结果一律进入 **标准 DataFrame + 元数据**（来源文件、sheet、页码），再进入现有清洗链。

### 5.2 清洗「四步」深化

1. **联合主键去重**：配置化主键列（如时间+账号+金额），`drop_duplicates`。  
2. **时间标准化**：识别时间列，统一为 **UTC 或本地 ISO 8601** 字符串。  
3. **金额**：币种检测与 **统一为「元」、两位小数**（汇率若需要可配置）。  
4. **业务规则异常**：负数、时间倒序、退款标记等，写入 **异常标记列** 而非静默删除。

### 5.3 单域分析算法（银行 / 通话 / 出行）

1. **银行**：滑动窗口统计、高频小额规则、**NetworkX 有向图 + 3～6 跳环路检测**、K-Means/DBSCAN、rolling 基线。  
2. **通话**：22:00–6:00 占比、**NetworkX** 度/PageRank/介数、序列模式（可调用现有库或简化启发式）。  
3. **出行**：敏感点库 + 折返模式；**R-Tree**（`rtree` 或 `scipy.spatial`）时空伴随查询。  
4. 输出：**结构化结果表 + 可供前端使用的聚合 JSON**。

### 5.4 多源碰撞与规则引擎

1. **碰撞服务**：输入多表、时间窗、空间半径，输出 **碰撞事件列表 + 可疑度分数**。  
2. **规则引擎**：规则 DSL 解析（YAML/JSON）、版本管理、执行顺序、与 Celery 任务集成。  
3. 结果写入 PG，供前端列表与 **线索生成** 消费。

### 5.5 特征融合与画像

1. **加权风险分**：资金/通信/轨迹/图中心性四维权重 **可配置**（按案件类型默认值不同）。  
2. **文本摘要**：模板 + 关键字段填充，或 LLM（若允许外网与合规审查）。  
3. **四维画像 API**：`GET /api/cases/{id}/persons/{key}/portrait` 返回分块结构化数据。

### 5.6 图数据库与业务图

1. Neo4j：**多类型节点**（人、账户、地点、事件）与多种关系；从话单/轨迹 **ETL 入库** 任务。  
2. **图算法服务**：社区发现、关键路径、介数等（Graph Data Science 或应用层 NetworkX）。  

### 5.7 报告导出

1. **PDF**：`weasyprint` / `reportlab` / HTML 模板转 PDF。  
2. **Word**：`python-docx` 填模板。  
3. 异步生成 + MinIO 暂存 + **短时签名 URL** 下载。

### 5.8 案件与文件绑定

1. **关联表** `case_files`：`case_id` + `file_id`，上传时写入。  
2. 分析任务 **仅处理指定 case 的文件**。

### 5.9 安全合规（后端）

1. **脱敏**：日志与 API 响应掩码规则；可配置字段级策略。  
2. **导出审批**：审批流状态机（可简化为「管理员审批表」）；通过后才生成完整导出文件。  
3. **审计**：导出、审批、敏感查询 **写入审计表**（扩展现有 `security_audit` 或独立表）。

## 六、全栈协同项（前后端共同约定）

| 事项 | 说明 |
|------|------|
| **人物主键** | Neo4j `User` 与 PG 人物/线索外键的统一标识（name 不可靠时改用 stable id） |
| **案件上下文** | 所有分析、线索、画像接口 **带 `case_id`**，与路由 `/cases/:caseId/...` 一致 |
| **错误码与 envelope** | 延续 `{ code, msg, data, request_id }`，前端统一拦截 |
| **分页与截断** | 大图谱、多线索、碰撞结果统一分页参数 `page`/`page_size` 或 `cursor` |
